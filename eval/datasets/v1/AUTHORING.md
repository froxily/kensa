# Evaluation dataset v1: authoring record

## Authorship and independence
- **Author:** all 40 cases were written by **Codex** (OpenAI, via the owner's ChatGPT login) acting as an independent author. Claude, which builds Kensa, wrote the authoring spec and the quality gates but **wrote no case content and assigned no labels**.
- **Isolation:** Codex was told not to read `backend/`, `frontend/`, `scripts/`, `knowledge/`, `eval/fixtures/`, `eval/reports/` or any root documentation. The cases were therefore written without knowledge of Kensa's signature rules, retrieval or prompts.
- **Labels** (category, kind, relevant evidence lines, fix keywords) were assigned at authoring time, before any Kensa component ran on the data.
- **Knowledge base:** the notes in `knowledge/` were committed (`deefdb8`) before any case was read, so they could not be fitted to the dataset.

## History
1. **v0 was rejected.** It was generated by one script from a single skeleton: every log was 34–36 lines, with the same repository name and the same filler. It was deleted unused, and the rejection is recorded in `mistakes.md`.
2. **v1 was re-authored** in four batches of 10 (c01–c10, c11–c20, c21–c30, c31–c40) under a stricter spec:
   - no templates or generator scripts
   - 50–160-line logs with real tool output and secondary errors
   - 3–6 repository files per case, including a workflow
   - unique names and wording
   - exact evidence line numbers

   Codex resumed several batches in fresh runs after its runs stopped mid-batch.
3. **Revision pass:** Codex's own review found artificial filler in c04, c05, c06 and c08. Those logs were rewritten with realistic tool output and their evidence ranges updated. **No labels changed.**

## Quality gates (`scripts/freeze_dataset.py`)
- **Loading:** every case loads, with exact evidence ranges inside the cited file and no blank ranges.
- **Shape:** logs are 50–160 lines; each case has 3–6 repository files, including a workflow.
- **Split counts:** as in the table above.
- **Anti-template check:** no two logs may share more than 25% of their non-trivial lines.
  - Lines that GitHub's runner, the checkout and setup actions, `docker version` and BuildKit's internal steps print in every real job are excluded by an **explicit allowlist**.
  - They are deliberately not excluded by corpus frequency, which would let a fully templated dataset pass.

## Freezing and use
- `MANIFEST.sha256` records a SHA-256 for every file. `scripts/evaluate.py` refuses to run if any file differs.
- **dev** split: used for M2 measurements and any tuning.
- **test** split: held out for the M5 milestone report. Evaluating it requires `--allow-test-split`.
- Any refreeze must be recorded here, with the reason.
- **Refreeze 1 (2026-10-30, before any evaluation):** the manifest now hashes line-ending-normalised content (CRLF to LF, BOM stripped), because git stores these files with LF line endings. No case content changed.
